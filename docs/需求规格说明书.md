# 社区智慧养老服务系统 软件需求规格说明书

## 1. 引言

### 1.1 编写目的
本文档定义基于 Spring Cloud Alibaba 的社区智慧养老服务系统的功能需求与非功能需求，作为系统设计、实现与验收的依据。

### 1.2 项目背景
随着人口老龄化加剧，社区居家养老服务的需求快速增长。传统养老服务存在信息不透明、服务调度效率低、健康数据分散、家属无法及时掌握老人服务进展等问题。本系统面向社区居家养老场景，为老人及家属、社区工作人员、服务商、平台管理员四类角色提供线上化的服务下单、智能派单、工单跟踪、健康档案管理与消息通知能力。

### 1.3 术语定义
| 术语 | 说明 |
|------|------|
| 工单 | 订单经智能派单后生成的服务执行单，由指定服务商履约 |
| 智能派单 | 按服务商评分、负载、完成率等多因子加权评分自动选择最优服务商的派单方式 |
| 微服务 | 按业务域拆分的独立部署服务单元 |
| 网关 | 统一入口，负责路由转发、鉴权与限流 |

## 2. 系统概述

### 2.1 系统目标
- 为家属提供在线下单、工单进度跟踪、服务评价与投诉、老人健康档案查看等能力；
- 为服务商提供接单与工单执行操作入口；
- 为社区工作人员与管理员提供服务目录管理、订单管理、智能派单、统计报表等能力；
- 实现服务的自动化调度与全流程数字化跟踪。

### 2.2 角色定义
| 角色 | 说明 |
|------|------|
| 老人及家属（FAMILY） | 服务的需求方，通过小程序下单、跟踪工单、验收评价、查看老人健康档案 |
| 社区工作人员（STAFF） | 服务目录维护、订单审核派单、工单管理 |
| 服务商（PROVIDER） | 承接工单，执行服务（开始/完成） |
| 平台管理员（ADMIN） | 系统管理、用户管理、全部数据查看与统计报表 |

## 3. 功能需求

### 3.1 用户中心
| 编号 | 需求 | 说明 |
|------|------|------|
| UC-01 | 用户登录 | 账号密码登录，签发 JWT 令牌并保存 Redis 会话 |
| UC-02 | 用户注册 | 用户名唯一校验，密码 BCrypt 加密存储 |
| UC-03 | 退出登录 | 删除 Redis 会话使令牌失效 |
| UC-04 | 用户管理 | 管理员分页查询用户、启用/禁用 |
| UC-05 | 修改密码 | 校验原密码，修改后强制重新登录 |
| UC-06 | 老人档案 | 家属查询自己绑定的老人列表 |
| UC-07 | 服务商列表 | 供智能派单调用的服务商信息（OpenFeign） |

### 3.2 服务与工单
| 编号 | 需求 | 说明 |
|------|------|------|
| OW-01 | 服务目录 | 服务项目的新增、修改、删除、查询 |
| OW-02 | 服务下单 | 家属选择服务、老人、地址生成订单（待派单） |
| OW-03 | 智能派单 | 按"距离+评分+负载+完成率"加权评分选择最优服务商，生成工单 |
| OW-04 | 防重复派单 | 状态校验 + Redis 分布式锁，同一订单不可重复派单 |
| OW-05 | 工单流转 | 已派单→服务中→待验收→已完成→已评价状态机，含取消/投诉分支 |
| OW-06 | 服务验收 | 家属对待验收工单进行验收 |
| OW-07 | 服务评价 | 已完成工单可评分（1-5）与文字评价 |
| OW-08 | 投诉 | 服务中/待验收工单可提交投诉 |
| OW-09 | 越权防护 | 仅工单所属服务商/下单家属/管理员可执行对应操作 |

### 3.3 健康档案
| 编号 | 需求 | 说明 |
|------|------|------|
| HR-01 | 健康档案 | 每个老人一份档案（身高、体重、血型、病史等），可保存与查询 |
| HR-02 | 健康指标 | 血压/血糖/心率/体温/体重指标录入与按类型查询 |
| HR-03 | 指标趋势 | 按指标类型返回最近 N 条升序数据，供图表展示 |
| HR-04 | 用药记录 | 用药信息的增删改查与提醒时间记录 |

### 3.4 消息通知
| 编号 | 需求 | 说明 |
|------|------|------|
| NF-01 | 站内信 | 消息发送、我的消息分页、已读标记、未读数统计 |
| NF-02 | 订阅管理 | 按消息类型订阅/退订 |
| NF-03 | 工单消息推送 | 工单状态变更（派单/开始/完成/验收/评价/投诉/取消）自动向家属与服务商推送站内信 |
| NF-04 | 推送容错 | 推送采用异步线程池执行，失败不影响主业务流程 |

### 3.5 统计报表
| 编号 | 需求 | 说明 |
|------|------|------|
| ST-01 | 汇总报表 | 订单数、营收、工单数、各状态工单数、平均满意度、投诉数 |
| ST-02 | 日趋势 | 近 N 天每日订单数与营收 |
| ST-03 | 服务类型排名 | 按订单数排名的服务类型统计 |
| ST-04 | 报表缓存 | 报表结果 Redis 缓存 30 秒，降低聚合开销 |

## 4. 非功能需求

### 4.1 性能
- 核心接口（登录、下单、查询）在常规并发下响应时间不超过 500ms；
- 网关对 user-center 路由配置 QPS 流控（Sentinel，阈值 100 QPS）。

### 4.2 安全
- 身份鉴权：网关统一校验 JWT（签名+有效期）+ Redis 会话（支持登出失效）；
- 访问控制：服务端按角色校验（@RequireRole），服务间调用经 OpenFeign；
- 输入防护：参数校验（Jakarta Validation）、XSS 过滤（输入转义）、SQL 注入防护（MyBatis-Plus 参数化查询）。

### 4.3 可用性
- 中间件（Nacos/MySQL/Redis）Docker 部署、数据卷持久化、容器自动重启；
- 推送、缓存等非核心能力故障不阻断主流程。

### 4.4 可维护性
- 微服务按业务域拆分，各服务独立数据库与独立部署；
- 提供 Knife4j 接口文档、部署说明、用户手册与测试报告。
