# 社区智慧养老服务系统 概要设计说明书

## 1. 总体架构

系统采用前后端分离的微服务架构：

```
┌──────────────────────────────────────────────────────┐
│ 前端：Vue3+Element Plus 管理端 / 微信小程序家属端        │
└───────────────────────┬──────────────────────────────┘
                        │ HTTP / JSON（/api/**）
┌───────────────────────▼──────────────────────────────┐
│ Spring Cloud Gateway 网关（8080）                      │
│ 路由转发 / JWT 鉴权 / CORS / Sentinel 限流             │
└───┬─────────┬─────────┬─────────┬─────────┬──────────┘
    │         │         │         │         │
┌───▼───┐ ┌───▼───┐ ┌───▼───┐ ┌───▼───┐ ┌───▼───────┐
│user-  │ │order- │ │health-│ │notify │ │statistics │
│center │ │work   │ │record │ │(8084) │ │(8085)     │
│(8081) │ │(8082) │ │(8083) │ │       │ │           │
└───┬───┘ └───┬───┘ └───┬───┘ └───┬───┘ └─────┬─────┘
    │         │         │         │             │ Feign
    │         └────Feign┼─────────┘             └──► order-work /stat
    └──Feign──┘         │
┌───▼───────────────────▼──────────────────────────────┐
│ 中间件（VMware 虚拟机 Docker，192.168.11.133）          │
│ Nacos 2.3.2（注册/配置中心） MySQL 8.0  Redis 7        │
└──────────────────────────────────────────────────────┘
```

### 1.1 技术栈
| 层次 | 技术 |
|------|------|
| 后端框架 | Spring Boot 3.2.4 / Spring Cloud 2023.0.1 / Spring Cloud Alibaba 2023.0.1.0，JDK 17 |
| 注册/配置中心 | Nacos 2.3.2 |
| 网关 | Spring Cloud Gateway |
| 流控降级 | Sentinel |
| 服务间调用 | OpenFeign + LoadBalancer |
| 持久层 | MyBatis-Plus 3.5.7 + MySQL 8.0 |
| 缓存/会话/分布式锁 | Redis 7 |
| 认证 | JWT（hutool-jwt）+ Redis 会话 |
| 接口文档 | Knife4j 4.5.0（OpenAPI 3） |
| 管理端 | Vue3 + Vite + Element Plus + Pinia + Vue Router + Axios + ECharts |
| 家属端 | 原生微信小程序 |
| 部署 | VMware + CentOS7 虚拟机，Docker 24.0.9 + Compose |

## 2. 微服务拆分

| 服务 | 端口 | 数据库 | 职责 |
|------|------|--------|------|
| gateway | 8080 | - | 路由、鉴权、跨域、限流 |
| user-center | 8081 | db_user | 认证、四角色、老人档案、服务商 |
| order-work | 8082 | db_order | 服务目录、下单、智能派单、工单、评价投诉、统计源 |
| health-record | 8083 | db_health | 健康档案、指标、用药 |
| notify | 8084 | db_notify | 站内信、订阅 |
| statistics | 8085 | -（聚合） | 报表聚合（Feign + Redis 缓存） |

服务间调用关系：
- order-work → user-center：派单时拉取服务商列表；
- order-work → notify：工单状态变更异步推送站内信；
- statistics → order-work：报表数据聚合。

## 3. 部署拓扑

- Windows 宿主机：运行 6 个 Spring Boot 服务（开发/演示）+ 管理端前端；
- VMware 虚拟机（CentOS 7，桥接 IP 192.168.11.133）：Docker 运行 Nacos / MySQL / Redis；
- 生产部署方案：前端 `vite build` 产物由虚拟机 Docker 中的 Nginx 容器托管，`/api` 反向代理至网关。

## 4. 数据库设计

每个微服务独立数据库（数据隔离）：

| 数据库 | 表 |
|--------|----|
| db_user | sys_user（四角色同表）、elder、family_binding、provider |
| db_order | service_catalog、service_order、work_order、dispatch_record、evaluation、complaint |
| db_health | health_record、health_metric、medication |
| db_notify | message、subscribe |
| db_statistics | 预留（当前报表为实时聚合） |

统一约定：主键自增、utf8mb4、逻辑删除（deleted 0/1）、create_time/update_time 自动填充。

## 5. 接口规范

### 5.1 路由约定
网关按前缀路由并剥离前缀：`/api/{service}/**` → StripPrefix=2 → 目标服务：

| 网关前缀 | 目标服务 |
|----------|----------|
| /api/user/** | user-center |
| /api/order/** | order-work |
| /api/health/** | health-record |
| /api/notify/** | notify |
| /api/statistics/** | statistics |

### 5.2 统一返回结构
```json
{ "code": 200, "message": "操作成功", "data": { }, "timestamp": 1792661704048, "success": true }
```
code=200 成功；401 未登录；403 无权限；其余为业务错误码（1xxx 用户域、2xxx 订单域、3xxx 健康域、4xxx 消息域）。

### 5.3 认证方式
请求头 `Authorization: Bearer <JWT>`；网关校验后向下游透传 `X-User-Id / X-User-Role / X-Username`。

## 6. 安全设计
| 安全项 | 方案 |
|--------|------|
| 身份认证 | JWT 签名+有效期校验 + Redis 会话比对（登出/改密即失效） |
| 访问控制 | @RequireRole 角色注解 + 业务级数据归属校验（服务商/家属/管理员） |
| SQL 注入 | MyBatis-Plus 参数化（#{}），禁止字符串拼接用户输入 |
| XSS | XssFilter 对请求参数/头/体做 "<"、">" 转义，前端 Vue 默认输出转义 |
| 并发安全 | 派单 Redis 分布式锁（SETNX+Lua 释放）防重复派单 |
| 参数校验 | Jakarta Validation（@NotNull/@NotBlank 等）+ 全局异常处理 |
